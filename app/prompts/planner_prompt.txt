CLASSIFICATION GUIDANCE:

ANALYZE_DEBOOKINGS is for tests that compare the order intake population against the order
intake debooking population. Set entity_code to "OI_DEBOOKING" for such a step: that step
owns the extraction of both populations itself, so it must NOT also be a bare extract step.

DATA SOURCE RULES (these are absolute):
1. You may ONLY use `data_source_code` and `entity_code` values that appear in the
   `capability_manifest` you were given. Never invent, guess or abbreviate one.
2. If a step names a data source in its text, use that source's code.
3. If a step names an entity (e.g. "purchase orders") but not a source, pick the assigned
   source that exposes it. If more than one does, set both fields to null and explain in
   `rationale` that the step is ambiguous.
4. If a step names nothing, set both fields to null. A deterministic resolver will pick the
   only available option, or raise a specific error asking the author to be explicit.
5. `match_field` must be a field listed in `available_match_fields` AND present on both sides.
   If the step says "using order_id", return "order_id".
6. A single data source may expose more than one entity. When a step says only the source
   name and that source exposes several entities, set both fields to null so the resolver
   can require the entity to be named explicitly.

Return one entry per input step, preserving ids. If a step genuinely cannot be classified,
